# Translating Orbita

Orbita's interface comes in **English, Spanish, German, French, Portuguese (Brazil), Ukrainian and Russian**. English and Russian are
complete everywhere: the interface, the rule-based engine that works without an AI key, the AI prompts, and the demo data. The other
languages cover the whole interface; the engine, demo data and offline text fall back to English, and a cloud model answers in the interface language.
The interface language follows the browser by default (Settings → Language lets you choose "Auto" or any language; the choice is also offered in the onboarding).
Adding another language is mostly a translation job: one JSON file and a few lines of code.

> **Review wanted.** Russian is the reference translation. Spanish, German, French, Portuguese and Ukrainian were drafted with AI assistance
> and checked mechanically (every message present, placeholders and plural forms valid), but not yet reviewed by native speakers.
> Corrections are very welcome: edit `src/i18n/locales/<id>.json` and open a pull request.

## How it works

The translation layer is small and has no dependencies (`src/i18n/`).

- **The English text is the key.** Code reads `t('Sign in')`. Untranslated text falls back to English, never to a technical key.
- Other languages are JSON dictionaries in `src/i18n/locales/<id>.json`, mapping the English text to the translation. They load lazily, so English users never download them.
- **Placeholders** use braces: `t('Hello, {name}', { name })`. A translation must keep the same placeholders.
- **Plurals** use `tn(count, '{n} day', '{n} days')`. In a dictionary a plural message is an **array of forms** in the order given by the
  language's `plural` list in `LOCALES` (English: `one, other`; Russian: `one, few, many, other`). `{n}` is filled in automatically.
- **Context** separates identical English words that translate differently: `t('Call', undefined, 'verb')` is stored under the key
  `verb\u0004Call` (a context, the control character U+0004, then the text).
- **Module-level constants** cannot call `t()` at load time. Mark the text with `msg('...')` and translate where it is shown with `t(value)`,
  or use a getter (`get label() { return t('Work') }`).
- **JSX with markup inside a sentence** uses `tx('Connected · {model}', { model: <b>Claude</b> })` from `src/i18n/react`.
- **Inline pairs** for text that is not UI chrome (AI prompts, demo content, rule-engine vocabulary) use `pick(en, ru)`.
- Keys must be **string literals** (no template strings with `${...}`). That is what lets the checker find all of them.

## Add a language

Say you add Italian (`it`).

1. Register it in `src/i18n/index.ts`:
   - add `'it'` to the `Locale` type,
   - add a row to `LOCALES`: `{ id: 'it', name: 'Italian', native: 'Italiano', tag: 'it-IT', plural: ['one', 'other'] }`
     (`plural` lists the CLDR plural categories of the language, in the order of your dictionary arrays),
   - add a loader to `loaders`: `it: () => import('./locales/it.json').then(m => m.default as Dictionary)`.
2. Create `src/i18n/locales/it.json`. The quickest start is to copy `es.json` (or `ru.json`) and replace the values (keep the keys).
   `npm run i18n:check` lists every message that is missing or has mismatched placeholders:
   ```bash
   npm run i18n:check             # fails on missing or malformed translations
   npm run i18n:check -- --strict # also fails on unused translations
   ```
3. Run the app (`npm run dev`), switch the language in Settings → Language and click through the screens. Long words may need a look on a phone.

That covers the whole interface. The next section is about the parts that think.

## The engine, the prompts and the demo data

- **The rule-based engine** (`src/ai/providers/mock-extract.ts`, `src/search/`, `src/ai/ask.ts`) understands English and Russian input at the same time,
  whatever the interface language is; what it *writes* follows the interface language. To teach it a new input language, extend the word lists and
  patterns there and add tests in both existing languages' style.
- **AI prompts** (`src/ai/prompts/`) exist in English and Russian through `pick`. For any other interface language the English prompts are used
  with a line from `answerLanguageNote()` asking the model to write the user-facing text in that language, so a new translation works with a
  cloud model out of the box; the structured JSON stays in English keys. Write dedicated prompts for the best results.
- **Demo data** (`src/db/seed/content/`) is written in both languages: records, quotes (a quote must be a verbatim part of its note, the
  seed validator checks it), people, patterns and reviews. Without a pack for your language the English demo is used.
- **Speech recognition** uses the `tag` of the locale (`de-DE`) for browser dictation, and the language code for server transcription.
- **Russian names** are declined where a sentence needs it (`src/i18n/ru-names.ts`); other languages show names as written.

## Tests

The test suite runs in the **Russian** locale (the app's original language), with a fixed time zone. A test of English behaviour calls
`setLocale('en')` and restores `'ru'` afterwards (see `src/__tests__/english-ui.test.tsx`, which walks the main screens and checks
that no Cyrillic leaks into the English interface). `src/__tests__/translations.test.tsx` checks every dictionary against the Russian one
(messages, placeholders) and walks the main screens in each Latin-script language. Add your language to its list.

## Style guide for translators

- Keep the tone of the original: calm, short, friendly, no jargon, no exclamation marks unless the English has them.
- Do not translate product names (Orbita, Aster, Anthropic, OpenAI, Claude, Supabase).
- The app talks to one person about their own thoughts: choose one form of address and keep it everywhere, and prefer wording that does not depend on gender.
- Keep the vocabulary consistent: *capture/record*, *decision*, *commitment*, *prediction*, *check-in*, *pattern*, *review*, *orbit*.
